# R8.1 — Simplified workspace telemetry

Prerequisite: rebased R8 (GoogleDrive 0.1.20, GitManager 0.1.19). This R8.1 GitManager step is 0.1.20. This incremental release uses the verified R7 commits as known ancestor guards for those repositories; GitRunner also verifies the required source versions. Core advances from 0.1.4 to 0.1.5 for the backwards-compatible status-event schema; existing app pins are unchanged.

## User workflow
Regular mode retains local/profile usage statistics and compact daily Drive aggregates, not individual workspace events. Manual enablement and managed Git activity use the same full account archive. Managed updates/exports enroll before execution; a durable controller monitors completion or cancellation and drains collected records before disabling an automatically started capture. A manual owner keeps it enabled. Paused or unresolved failed jobs retain capture until recovery/cancellation. Multiple overlapping owners share one actual capture period. Failed drains retain pending data and retry. Force update does not disable capture. Disabling manual ownership during an active job leaves job-owned capture running.

Telemetry page: enable/disable, Force update, Export telemetry; choose explicit dates or recent capture count and see effective range. Capture periods are recorded from R8.1 onward (up to 256/30 days). Existing active capture may be adopted with estimated start. Historical starts cannot be inferred. Export ends at current time for count selection, including gaps. One Share activity action prepares diagnostics plus correlated telemetry; sharing the actual repository export remains separate. Periodic allowlisted status records and current status are included in exports. Successful archive reads are not presented as errors merely because providers are delayed or coverage is limited; real read/upload failures are shown as incomplete.

All existing permanent IDs and remaining criteria retained.

## Boundaries
Existing integrated producers share the capture state; this does not add Translate/Azure instrumentation, provider-wide coverage, or new app token counters. Daily Drive totals are account-wide, retained in durable storage with a periodic verified backup file (automatic restore not implemented); do not sum these totals with detailed event totals. Regular local profile statistics/backup behavior is unchanged. Older app Core pins remain 0.1.4. Standalone workflow dispatch outside a managed job is not a managed capture owner. Provider discovery may lag a job and archive reads remain bounded to existing limits (31 days, 160 chunks, ~8 MiB). Reported status samples are compact; current status is embedded. Capture lifecycle polling is approximately one minute with jobs and five minutes for manual-only status; transitions may not be instantaneous. Enrollment failure does not block the underlying Git operation and is reported in lifecycle diagnostics. Live deployment, native sharing and device acceptance required. Automated browser navigation blocked by environment policy; no mobile browser pass claimed.

Share a completed job using its single Share activity action. Confirm no loss on a simulated or actual failed drain. No separate telemetry status files needed.
