### TEL-01 — architecture and event contract

Use the existing ecosystem, not a new repository or commercial analytics service by default. PWA-Core owns portable versioned event contracts, instrumentation and sanitizer helpers; PWA-GoogleDrive owns the existing account-level authorization and Drive archive; PWA-GitManager owns collector scheduling, provider adapters and the UI; PWA-GitRunner emits bounded native execution observations. Ciyan instruments direct Azure requests and translation cache behavior; AppLauncher exposes/forwards shared service access; WorldGen/Ascendant instrument applicable Worker entry points and common client operations where useful. Existing older Core pins must not change incidentally: explicitly assess required dependency changes, test and include in manifest only as needed. No Chronicle implementation.

Schema 2 normalized event envelope: eventId (stable per observation), schema, source, kind, severity, occurredAt (UTC), ingestedAt, observedAt when appropriate, app/service and version, operation/stage, outcome/status/error code, optional duration/units, correlation (jobId, attemptId, workflowRunId, runAttempt, repo, commit, requestId, deploymentId), provenance (instrumented/provider/import), confidence (observed/estimated/sampled/unknown), coverage flags. Fields source-specific and allowlisted; no free-form arbitrary payloads. Distinguish event instants, intervals, snapshots and usage deltas; preserve original provider timing and record collection lag. No fabricated causal links: exact IDs/refs preferred; contextual time overlap explicitly marked. SHA is operational metadata, not profile identity. Stable provider IDs plus run attempt/version prevent duplicate usage. Backfilled timestamps may arrive out of order. Legacy network-v1 read adapter preserves original meaning; never interpret UTF-16 counts as network bytes. Explicit coverage for unsynchronized clients and unavailable provider fields.

Security: account-owned archive, not profile-specific; owner must explicitly enable workspace collection using existing authorized Google session plus administrator unlock. Persistent server authority limited to opted-in account and revocation epoch, not stored browser cookies or password. Resolve account via trusted Profiles service; no caller-supplied account/email mapping; background jobs use narrow server-side capability scoped to destination and telemetry append, not arbitrary Drive access. Internal routes must be inaccessible via public proxy and authenticated/allowlisted; no generic ingestion proxy. Use bounded schemas, origin/CSRF guards, producer auth, per-source size/rate limits and replay protection. Existing GitHub runner callbacks stay narrowly scoped to active assignments; telemetry must not grant write credentials or change job state. Late terminal logs may be imported via read-only collector, not re-enable a stale runner. Store provider tokens as Worker secrets only; never in browser, patch, export, Drive, console or logs. Raw headers, cookies, password, bearer tokens, OAuth code/state, API keys, signed URLs, env dumps, personal identifiers/IPs, profile/learning data, paragraph text, translation output, speech text/SSML/audio and private source contents excluded. Sanitize before buffering, upload and sharing; allowlist fields from native Worker events; GitHub log messages treated as untrusted, strip unsafe fields/known secret patterns and discard suspicious/unparseable content with explicit dropped counters. Do not promise arbitrary free-text redaction is perfect; structured records default; sanitized bounded excerpts or step logs only when safe, never blindly copy entire raw provider archives. Test with canary secrets including old x-git-unlock header. No automatic external sharing: automatic upload only to user's Drive; native sharing initiated by user. Admin gate for sensitive diagnostic exports and configuration, preserve read-only status visibility for authorized owner.

### TEL-02 — durable Drive archive, retention and scheduling

Current PWA-GoogleDrive v0.1.13 NETWORK_TELEMETRY.md and worker/network-telemetry.js already implement account-scoped journal, first flush ~10 min, subsequent >=1 h, bounded 1024 live + frozen entries, idempotent batch retries, lazy ~30-day cleanup, existing drive.file authorization. Extend rather than replace wholesale; preserve existing data and backup/revoke semantics. Keep archive under AppLauncher Profiles/telemetry, outside profiles and objects. Suggested layout: existing network-v1 files remain in place; v2/YYYY/MM/DD/ immutable compressed JSONL or JSON chunks with manifests/index metadata (min/max event time, source counts, bytes, IDs, hash, schema). Day folder by UTC freeze date is not a reliable event-date filter: index actual timestamp span, include late-arrival chunks. Logical single timeline, no giant mutable file; one account directory. Suggested batch 256–512 KiB uncompressed or 500–1000 records (tune by measurement); flush when threshold reached or ~15–60 minutes when data exists, job terminal collection queued promptly, no empty writes. Bounded pages, incremental cursor/index reconciliation, ack only after durable commit, stable pre-generated batch ID/duplicate check, never prune an unacknowledged batch as if saved. Persist cursors and retry state across redeploys; exponential backoff and provider Retry-After; explicit loss/gap counters if limits exceeded. Priority reserve for errors, final job records and usage aggregates; coalesce repetitive successes. Client events held in bounded IndexedDB queue where practical, flush on next connected use; cannot collect offline client events that never reconnect, or guarantee capture if process crashes before commit. Avoid blocking profile serialization or job state transitions: separate telemetry queue/DO where needed, no global workspace execution lock for collection or reports; bounded account writer to prevent Drive overload. No recurring idle GitHub runner required.

Proposed retention defaults: detailed events and sanitized log excerpts 30 days and 250 MiB max in Drive, whichever expires first; daily/monthly compact usage rollups 12 months (separate small 5 MiB target cap); transient pending server spool target 8 MiB/48 h, client spool target 1 MiB/7 days, bounded by actual Free-plan constraints; preserve high-priority summaries and mark overflow. These are initial tuning targets, not claims of measured storage. Prune in bounded scheduled maintenance, including when account idle but authorized; daily maintenance only for enrolled accounts with data, no perpetual busy loop. Use indexed creation time/actual event age and safe folder/ownership boundaries; never touch backup history, unrelated files, or user's separately shared copies. Clear pending telemetry on account revoke, stop provider polling; leave existing Drive files user-owned. Confirm old legacy telemetry retention compatibility. Data retention independent of GitManager activity list, patch/R2 artifact lifecycle and provider log expiry. Show oldest retained timestamp and deletions/coverage. Export time window may exceed available detail; never report full coverage if expired. No new paid storage requirement. Acceptance: Drive unavailable/auth expiry, lost ack, duplicate chunk, restart, partial writes, late arrival, bounded size, aged chunks, manual import, multi-account isolation, legacy compatibility and zero impact on backup correctness.
