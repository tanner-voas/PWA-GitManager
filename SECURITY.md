# Security and failure recovery

This application is a privileged development service, not a public multi-user Git client. The public UI and static app assets contain no secrets. The GitHub App private key and one administrator unlock are Worker secrets; the high-entropy runner callback secret is shared only with the private execution repository's Actions secret. Authentication checks the existing verified profile status endpoint (`/_profiles/v1/status`) against an explicit configured administrator email. Exact same-origin CSRF checks and an independent unlock are required for every user mutation. Administrator unlock is a 30-minute origin-bound HMAC-signed HttpOnly cookie, not a raw password header. Lock clears the local cookie; rotating ADMIN_UNLOCK invalidates all prior cookies. Do not enable request-body logging or custom logging of credentials. Do not enable arbitrary Google accounts. Rotate secrets if exposed and revoke the GitHub App installation if necessary.

The runner uses a one-hour GitHub App installation token for read access during preparation, and a new token scoped to only the target repo for publishing. Tokens are injected into Git command environment, not stored in remote URLs or Git config; checkout artifacts are inspected for credential-like config. The untrusted candidate test stage has read-only workflow permissions, no shared runner secret, no App key and no write credential. It receives a private prepared archive. Publication uses the separate original artifact, independently rechecks its hash and Git identity, and never executes candidate scripts. This is not a sandbox for adversarial uploads: approved changes can modify future CI and deploy code. Inspect patches from a trusted source, especially changes to workflow files, Workers and controller policies. Do not publish malicious or unknown code. Protect PWA-GitRunner and its Actions settings; a malicious change to the trusted runner can defeat the model. The Worker refuses to dispatch to a public runner, because artifacts can contain private source. No secrets should be included in a patch or export.

R2 upload bucket must be private and have a seven-day lifecycle deletion rule. GitHub artifacts have one-day retention and are only accessible to authorized repository readers. Job metadata persists in Durable Objects; the most recent 100 jobs are listed and the last 64 attempts per job are retained. GitHub workflow logs are private. Diagnostic JSON can include repository names, hashes and Git error messages; inspect it before sharing externally. No local full clone is retained by the Worker. The system has no automatic spending guarantee; set GitHub Actions budgets, monitor R2 storage and Workers usage. A 12 MiB package limit is a conservative memory budget; export archives use GitHub Actions instead of Worker buffering.

A failed/paused job holds the workspace lock; inspect the exact run, then resume or cancel. Only explicit pre-write automation observation timeouts receive up to two automatic retries via a durable alarm; uncertain writes and dispatch outcomes do not. The watchdog detects completed runners without a final callback and pauses for recovery. If an external automation is stuck, trigger the current tag/reconciliation workflow from the repository view. If a write was granted but callback lost, the resume flow checks GitHub before another attempt. If a PR branch was pushed but PR creation failed, inspect the branch and create the PR on GitHub; resume will discover it. Do not force-push main or production. Do not rerun old Actions attempts manually: use a new attempt from the app. Cancel cannot undo prior commits; use a new versioned revert patch if necessary. If credentials, deployment, or the controller itself are broken, use GitHub web UI and Cloudflare dashboard or an independent Git client. Standalone `pwa-git-api` is separate from AppLauncher production and can repair a broken launcher, provided the manager backend itself works. Manual PR merging is outside the direct-write version gate; check current base version and use squash merge for one versioned commit. No automatic branch deletion or destructive reset is exposed.

After upgrading from v0.1.2 or earlier, rotate ADMIN_UNLOCK in Cloudflare and clear or restrict historical logs containing the old x-git-unlock header. Never share unredacted logs. Cloudflare default request logs do not include POST bodies; retain that configuration. Lock clears this browser cookie only; secret rotation invalidates every outstanding unlock cookie.
