# R9 — Capture continuity, export recovery, provider usage

Baseline: the completed R8/R8.1 successive update and lightweight ten-repository export `git-workspace-743cc692.tar.gz`. GitManager 0.1.20, GoogleDrive 0.1.21, Core 0.1.5, Ciyan 0.9.27. The prior review established 43.646s remote export completion, then a device-side preparation delay; the actual cause of the earlier stalled attempts remains unknown. The capture snapshots showed 71 pending detail requests before automatic shutdown and zero at the next manual activation.

## Changes
- TEL-04/TEL-02: lifecycle status and account archive status are observational; public status reads never invoke collector ensure/stop. Legacy poll cannot reactivate a stopped collector. Explicit preparation uploads route through the serialized capture controller in deployed Workers; a paused same-owner checkpoint remains visible in terminal status snapshots. Explicit revocation, account/epoch isolation, expiration and upload-before-disable are retained. The prior lost checkpoint cannot be reconstructed.
- JOB-02/UI-08/TEL-03: archive preparation exposes actual locating, byte-count download, verification and ready stages. Sixty seconds without progress or five minutes total aborts preparation, not the export job; cancellation and retry reuse the completed artifact. Content-Length is passed only when trustworthy; unknown totals use an indeterminate progress bar. Existing ZIP bounds, exact gzip member, CRC and format checks remain. The last 12 bounded preparation attempts (stage, bytes, elapsed, result) are attached to the job, even in Regular mode, and terminal observations can enter a full capture. Client diagnostic submissions are best effort. No raw error text, secrets or signed storage URLs. Native sharing is still separate from preparation and user activation.
- TEL-12/UI-05: last 15 minutes, one hour and 24 hours shortcuts use tap time, and local datetime input styling constrains iOS intrinsic width. Existing capture counter and single activity share remain unchanged.
- TEL-09: actual Google Translate attempts after budget reservation report request, estimated characters, reservation, outcome, status and duration via trusted existing Profiles service binding. No quota changes, no provider retry or text logging. Cloud provider billing figures, cache-hit archival and quota reconciliation remain open. Existing Core client pins need not change for server-only instrumentation.
- TEL-10: Ciyan reports Azure synthesis, prefetch and playback cache hits, including unsuccessful or aborted requests, without SSML, voice, region, key or content. Cache hits do not count as paid requests; in-flight requests are counted once. Browser reporting uses the existing same-origin Google session/CSRF guard and is best effort; signed-out/offline or interrupted reports can be absent. Character counts are Unicode code point estimates, not authoritative Azure billing. No new Azure requests or credentials.
- TEL-16/TEL-08: provider usage is aggregated by UTC day, per authorized Google account, in the existing durable Regular usage totals with scheduled verified Drive backup. Full capture archives the same observations individually; do not sum both representations. Recent-ID dedup is bounded (512 IDs), daily history 31 days; no new profile schema or automatic restore. Regular mode retains compact totals, not individual provider events. Provider records are timestamped at account ingestion, not provider billing time. Provider usage does not enable full capture.

## Validation and boundaries
GitManager/GoogleDrive/Core unit tests and Ciyan focused speech tests cover cancellation, timeout, readonly status, pause/resume, provider errors and privacy. Live GitHub/Cloudflare, iOS transfer/sharing and billing are not reproduced by local tests. Core Worker must deploy through its existing Cloudflare pipeline, independently of app pins; no deployment permissions are changed. Ciyan is updated only for Azure instrumentation and its adjacent identity backup migration; automatic GoogleDrive reconciliation can advance its base commit before its patch. All existing permanent roadmap IDs and remaining acceptance criteria are preserved.
