## Evidence and scope

R7 reports and screenshots show client 0.1.16 despite a 0.1.17 backend and published pin; the checkpoint restored, but the old frontend still hides disabled status sharing. The existing AppLauncher offline SW intentionally waits for explicit activation and keeps old release assets consistent. That is a plausible explanation, not proof of the deployed cache state. Do not auto-reload active sessions or purge caches. First use the existing launcher update button to activate R8; the R8 frontend then compares its version with the authenticated backend response and provides explicit host update action. A mismatch may also reflect deployment order. Reports carry both versions when available. UI-06/UI-07, QA-01 remain open for actual iOS acceptance.

TEL-04/TEL-12: status sharing available enabled, disabled or status-unavailable; no collection action is required. A new RPC-only account owner hash derives from the live signed session and authorization epoch; not an append capability, never included in the browser report. Admin unlock is required for a paused checkpoint summary, which contains only counts and timing, no repo/run IDs, credentials or raw checkpoint. Same account and epoch plus 48h validity required; old Drive deployment returns minimal paused status until upgraded. R7 collection cadence unchanged.

TEL-13: activity has separate archive-only Share telemetry and explicit Upload & prepare telemetry. This bounded, non-destructive operation drains verified Drive records, then producer batches, then Drive again. Does not start workflow scans, enable collection, or freeze concurrent producers. Disabled archive reads normally; incomplete uploads explicitly reported, retained pending records are not intentionally removed by this action. The export end time is recalculated after upload. Late workflow details may still be missing. The action is CSRF/admin gated; it is manually requested and may consume Drive API calls. Existing provider limits apply; no automated repeated drain. TEL-12 human-readable warnings preserve machine codes in JSON.

TEL-06: expand GitManager Worker instrumentation to authorized workflow dispatch and successful authenticated/assigned runner claim/candidate/published/finish callbacks. Token/package/progress, polling, archive queries and credentials excluded. GoogleDrive account coordinator measures selected profile create/rename/commit request service time and queue time, only if authorized archive enabled for the same epoch. These are request observations, not native platform totals/CPU or additional Drive consumption; do not add to Drive operation counts. No body, path, profile ID, token, or URL recorded. Both sources are partial coverage. TEL-14 manual links retained. No new provider permissions. TEL-09/10 Translate/Azure and TEL-16 Standard aggregates are deliberately deferred to a later batch rather than changing parallel Ciyan/Core or introducing unapproved semantics.
